# Catalpa Automations — Commercial Pack (Solution-First)

> **Have a Ghana lawyer review before use.**  
> These are plain-language business templates for Accra / Kumasi SMEs. They are **not** formal legal advice and do **not** replace a solicitor’s review under Ghana law.

---

## What “solution-first” means

1. Catalpa builds and shows a **live WhatsApp bot + dashboard** for the client’s business.  
2. **No development fee** is charged before the client can see and try that live system.  
3. When the client is happy, they sign the **live commitment** (order form) and start paying the agreed plan.  
4. Until then, either side can stop the pilot cleanly — no surprise bills, no hostage of the client’s customer data.

This pack protects **Catalpa** from free-work abuse and protects the **client** from surprise charges and lock-in tricks.

## When to use which document

| Doc | Use when | Who signs |
|-----|----------|-----------|
| **01-pilot-agreement.md** | Before you connect Meta / WhatsApp and stand up the demo bot | Client + Catalpa (short) |
| **02-live-commitment.md** | After the client has seen the live bot + dashboard and wants to go paid | Client + Catalpa (order form) |
| **03-scope-boundary.md** | Attach to pilot *and* live commitment — tick what’s in / out | Both (checklist) |
| **04-handoff-and-exit.md** | Attach to live commitment; also use when a client leaves | Both (exit rules) |

**Suggested flow**

```
Intro call / shop visit
    → Pilot Agreement + Scope Boundary (Day 0)
    → Live WhatsApp bot + dashboard (7–14 day pilot)
    → Client decides
         ├─ Yes → Live Commitment + Scope + Exit docs → first payment
         └─ No  → Disconnect bot, export any client data, done
```

Do **not** start Meta Ads spend or long custom builds before the pilot agreement is signed. Ads money is always the **client’s**.

## Payment triggers (keep it simple)

| Moment | What is owed | What is *not* owed |
|--------|--------------|---------------------|
| Pilot starts | Nothing to Catalpa for build time | No “discovery fee”, no “deposit for coding” |
| During pilot | Client pays **their own** Meta / WhatsApp / ad spend | Catalpa does not invoice for pilot build |
| Client says “go live” on a paid plan | First period fee (or setup-after-go-live fee) via MoMo / Paystack **before** full production cutover | No back-billing for pilot days |
| Each billing cycle | Agreed monthly SaaS and/or per-order fees | No silent price jumps mid-cycle |
| Extra work outside scope | New written quote; work starts only after client accepts | No “we’ll just add it” then surprise invoice |
| Client cancels with notice | Fees for the notice period only (see live commitment) | No exit penalty, no data ransom |

**Rule of thumb:** money moves when the client **chooses a plan after seeing the live system**, or when they **approve a separate change quote**.

## Recommended GHS packaging (bands, not fake precision)

Bands below are **working ranges** for Ghana SMEs (fashion, food, beauty, spare parts, clinics, tutors). Adjust for complexity, staff count, and catalog size. Quote a **clear number** on the live commitment — these ranges only guide the sales conversation.

### A) Setup after go-live (one-time)

Charged **once**, only after the client commits to a paid plan and the system is accepted as “done” for the scoped list.

| Band | Rough GHS | Fits |
|------|-----------|------|
| Light | **1,500 – 3,000** | Small catalog, one WA number, basic order + MoMo link |
| Standard | **3,000 – 6,000** | Catalog + dashboard + dispatch alerts + staff training |
| Heavy | **6,000 – 12,000** | Multi-location / multi-number / richer flows (still inside scope list) |

Use this when the client prefers a lower monthly and can pay a one-time go-live fee. Still: **no** setup fee during the free pilot.

### B) Monthly SaaS (hosted bot + dashboard)

| Band | Rough GHS / month | Fits |
|------|-------------------|------|
| Starter | **150 – 400** | Low volume; core bot + dashboard |
| Growth | **400 – 1,200** | Steady orders; support window; light tweaks |
| Managed | **1,200 – 3,000** | Higher volume + Catalpa babysits ops / weekly health |

Pair with optional **Click-to-WhatsApp ads management** (agency wrap) around **1,500 – 4,000 GHS / month** — **ad spend stays on the client’s Meta billing**.

### C) Per-order / per-paid transaction

| Band | Rough GHS | Fits |
|------|-----------|------|
| Flat per paid order | **0.50 – 2.00** | Chop bars, boutiques with many small tickets |
| Or % of paid order | **1% – 3%** | Higher ticket (spare parts, fashion wholesale) — cap if needed |

Use alone for thin SaaS, or **mix**: lower monthly + small per-order. Always define what counts as a billable order (e.g. Paystack/MoMo **paid** webhook only — not abandoned chats).

### Mixing (common Accra / Kumasi deals)

| Mix | Example shape | Why it works |
|-----|---------------|--------------|
| Setup + monthly | 3–5k after go-live + 400–900 / mo | Covers build cost; retainer keeps bot healthy |
| Monthly only | 800–1,500 / mo | Client hates one-time bills; Catalpa recovers over 3–6 months |
| Monthly + per-order | 200–500 / mo + 1 GHS / paid order | Aligns with volume; fair when quiet months happen |

Write the mix in **GHS**, name the billing day, and name MoMo / Paystack as the collection method on the live commitment.

## Fairness checklist (both sides)

**For Catalpa**

- [ ] Pilot has an end date (e.g. 7–14 days)  
- [ ] One pilot per business unless Catalpa agrees in writing to extend  
- [ ] Scope Boundary signed — no free ERP / native app / unlimited custom  
- [ ] Catalpa owns bot IP / platform code; client does not get source as a “gift”  
- [ ] Paid work only starts after Live Commitment + first payment  

**For the client**

- [ ] They see a live bot + dashboard before paying Catalpa  
- [ ] Meta Ads / WhatsApp fees are theirs and transparent  
- [ ] No ROAS promise in writing  
- [ ] Cancellation notice is clear; no hostage of their customer data  
- [ ] Change requests get a new quote — no surprise mid-month bills  

---

## Pairing with the CTWA spine

Catalpa’s core: **Meta Ads → Click-to-WhatsApp → Catalpa bot (chat / orders) → dashboard → dispatch**.

- Pilot = prove that spine on **their** number / catalog with **their** ad spend.  
- Live commitment = rent the spine (SaaS / setup / per-order), not buy Catalpa’s platform.  
- Exit = take **their** customer & order data; leave Catalpa’s bot code and platform.
